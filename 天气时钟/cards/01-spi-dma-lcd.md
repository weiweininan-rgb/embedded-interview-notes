# SPI + DMA 刷屏（ST7789V）

## L1 电梯陈述

DMA（直接存储器访问）是由 DMA 控制器在内存与外设数据寄存器之间自动搬运数据的机制。显示项目中，大块 RGB565 像素可由 DMA 连续写入 SPI 数据寄存器，SPI 再按时钟从 MOSI 发给 ST7789；CPU 只负责配置传输和处理完成事件，避免逐字节轮询占用 CPU。

## L2 架构与数据流

```text
像素缓冲区（内存）
        │ DMA 读取
        ▼
SPI 数据寄存器
        │ SPI 生成 SCK、从 MOSI 串行输出
        ▼
ST7789 显存
        │ DMA 传输完成中断
        ▼
释放二值信号量 → 唤醒等待的 UI/显示任务
```

DMA 负责“搬数据”，SPI 负责“按串行时序发送数据”，二者不是替代关系。DMA 不会直接向屏幕发送像素，也不自动解决显示撕裂；它主要降低 CPU 在大量数据传输中的等待开销。

## L3 机制深挖

### 1. DMA 是什么，解决什么问题

没有 DMA 时，CPU 往往要重复执行：等待 SPI 发送寄存器空 → 写一个字节 → 再等待。整屏或大图刷新时，这种逐字节轮询会占用大量 CPU 时间。

使用 DMA 时，CPU 一次性配置：

```text
源地址：像素缓冲区首地址
目的地址：SPI 数据寄存器地址
传输数量：需要发送的字节/半字数量
方向：内存 → 外设
```

随后 DMA 按外设请求搬运数据，CPU 可以执行其他任务或进入等待。传输结束后，DMA 产生完成标志或中断。

### 2. DMA 关键配置项

| 配置 | 含义 | ST7789 SPI 刷屏的常见选择 |
| --- | --- | --- |
| 源地址 | 数据从哪里来 | 像素缓冲区 |
| 目的地址 | 数据搬到哪里 | SPI 数据寄存器 |
| 方向 | 内存与外设的流向 | 内存 → 外设 |
| 内存地址递增 | 每搬一次源地址是否前移 | 开启，连续读取像素 |
| 外设地址递增 | 每搬一次目的地址是否前移 | 关闭，始终写同一个 SPI 数据寄存器 |
| 数据宽度 | 每次搬运 8/16/32 bit | 必须与 SPI 数据位宽、缓冲区格式匹配 |
| 传输模式 | 传完停止或自动循环 | 刷屏通常用普通模式 |
| 优先级 | 多路 DMA 竞争时的服务顺序 | 按实时性配置，不能只靠高优先级掩盖设计问题 |

### 3. 普通模式与循环模式

- 普通模式：传输指定数量后停止，适合一次图片、一次局部区域刷新。
- 循环模式：传输结束后自动从头开始，适合 ADC 持续采样、UART 环形接收等连续数据流。

屏幕刷新通常是“准备一帧或一个区域 → 发一次 → 完成”，因此更适合普通模式。若错误使用循环模式，DMA 可能重复发送旧缓冲区内容。

### 4. DMA、轮询、中断的区别

| 方式 | CPU 做什么 | 适用情况 | 代价 |
| --- | --- | --- | --- |
| 轮询 | 不断检查状态并处理每个字节 | 极少量数据、简单初始化 | CPU 忙等，吞吐大时浪费明显 |
| 中断 | 每来一个事件/字节就进中断处理 | 低速、零散事件 | 高频数据会造成频繁中断 |
| DMA | 配置一次，由硬件连续搬运 | 大块、连续、高频数据 | 配置和缓冲区管理更复杂 |

面试可说：**DMA 不是“比中断高级”，而是适合大块连续数据；中断适合通知传输完成或处理离散事件。**

### 5. DMA 完成后为什么要用中断/信号量

在 FreeRTOS 教程版中，显示任务启动 DMA 后等待二值信号量；DMA 完成中断调用 `xSemaphoreGiveFromISR()`，必要时通过 `portYIELD_FROM_ISR()` 让被唤醒的高优先级任务尽快运行。

```text
显示任务：启动 DMA → xSemaphoreTake(..., portMAX_DELAY) → 阻塞，不占 CPU
DMA 中断：传输完成 → GiveFromISR → 显示任务变为就绪
```

这样不会让任务不断轮询 DMA 完成标志。中断里只做清标志、释放信号量等短操作；下一次显示决策和大块处理仍由任务完成。

### 6. 常见风险与排查

1. **缓冲区提前被修改或释放**：DMA 仍在读内存时，不能复用、释放或改写该缓冲区。
2. **重复启动 DMA**：上一笔未完成就重配源地址、长度或启动下一笔，可能破坏传输；应等待完成信号量。
3. **长度/位宽错误**：RGB565 为每像素 16 bit，传输数量和 DMA/SPI 位宽不匹配会导致颜色错乱、图像错位。
4. **DMA 请求或 Stream/Channel 映射错误**：DMA 没有接到 SPI 外设请求，表现为不传输或只传一部分。
5. **未清完成/错误标志**：下一次传输可能无法正确启动或误判完成。
6. **显示窗口与像素数量不一致**：即使 DMA 正常，窗口范围错误也会造成图像错位或残留。

### 7. DMA 与显示撕裂的边界

DMA 能降低 CPU 忙等，但不天然消除撕裂。撕裂通常来自 LCD 扫描显示期间，前后两帧在不同区域交错；可进一步通过局部刷新、双缓冲、在合适的帧同步时机更新等方式改善。当前工程不能宣称已经实现双缓冲或帧同步。

### 八股追问

**DMA 是什么？**

DMA 是独立于 CPU 的数据搬运控制器。CPU 配置源、目的、长度和方向后，DMA 在内存与外设间自动传输数据，结束后通过标志或中断通知 CPU。

**为什么 SPI 刷屏适合 DMA？**

RGB565 像素数据量大且连续。若 CPU 逐字节轮询 SPI，会长期忙等；DMA 可连续把像素写入 SPI 数据寄存器，让 CPU 处理其他任务。

**DMA 和 SPI 分别做什么？**

DMA 将内存缓冲区的数据搬到 SPI 数据寄存器；SPI 产生时钟并将数据从 MOSI 串行输出至 ST7789。

**DMA 和中断有什么关系？**

DMA 负责大块传输；DMA 完成中断用于通知传输结束。中断不应逐字节搬运显示数据，否则会产生过多中断开销。

**DMA 传输期间 CPU 能否修改缓冲区？**

不能随意修改。DMA 正在读取该内存，修改会造成显示内容混杂；必须等完成事件到来，或使用双缓冲。

**为什么外设地址通常不递增，内存地址递增？**

像素数据在内存中连续排列，需要依次读取；SPI 只有同一个数据寄存器，DMA 每次都应写回这个固定地址。

**DMA 能完全避免屏幕撕裂吗？**

不能。DMA 解决的是 CPU 搬运开销；撕裂与屏幕扫描和帧更新交错有关，通常还需要双缓冲或帧同步策略。

**DMA 出现“只显示一半”怎么排查？**

先核对显示窗口、像素数量和 RGB565 长度；再查 DMA 长度/位宽、SPI 配置和完成标志；最后检查缓冲区是否被提前修改、DMA 是否被重复启动。

## L4 权衡与替代方案

- 小数据或初始化命令：轮询实现简单，调试直观。
- 大块像素：DMA 更合适，减少 CPU 占用。
- 若需要进一步减少撕裂：可以改为双缓冲或帧同步，但会增加 RAM 占用和实现复杂度。
- 若多个任务都要显示：可采用单 UI 任务 + 消息队列，统一管理 SPI/DMA；FreeRTOS 教程版采用此思路。
